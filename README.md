# FaceID SBT Identity (be-40)

Face-based identity enrollment and ZK-auth verification with:
- On-chain SBT identity + on-chain auth proof verification
- Encrypted face template storage (Supabase)
- Realtime proof stream + CSV export

## Project layout
- `contracts/` Solidity contracts (IdentitySBT + Groth16 verifier)
- `circuits/` Circom ZK circuit and build notes
- `relayer/` Relayer for optional off-chain storage (Supabase)
- `web/` Frontend app (Vite + React)

## Prereqs
- Node.js 18+ (recommended)
- npm
- A wallet with Base Sepolia test ETH
- Supabase project (URL + keys)
- Circom + snarkjs (for generating ZK artifacts)

## Quick start (frontend)
1) Install deps:
```
cd web
npm install
```

2) Configure `web/.env`:
```
VITE_WALLETCONNECT_PROJECT_ID=...
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
VITE_RELAYER_URL=http://localhost:8787/proofs
VITE_ZK_WASM_PATH=/zk/face_auth.wasm
VITE_ZK_ZKEY_PATH=/zk/face_auth.zkey
VITE_ZK_VKEY_PATH=/zk/face_auth.vkey.json
```

3) Start the app:
```
npm run dev
```

## Contracts
Contracts:
- `FaceAuthVerifier.sol` (Groth16 verifier generated by snarkjs)
- `IdentitySBT.sol` (SBT + auth proof submit + events)

Deploy order:
1) Deploy `FaceAuthVerifier` (no args)
2) Deploy `IdentitySBT` with:
   - `initialOwner` (address)
   - `verifierAddress` (from step 1)

Update:
```
web/src/lib/contract.js
```
with the new `IDENTITY_CONTRACT_ADDRESS` and `IDENTITY_OWNER_ADDRESS`.

## ZK circuit artifacts
ZK circuit: `circuits/face_auth.circom`

Build artifacts (requires `circom` and `snarkjs`):
```
cd circuits
npm install
mkdir build
circom face_auth.circom --r1cs --wasm --sym -o build -l node_modules
snarkjs powersoftau new bn128 17 pot17_0000.ptau -v
snarkjs powersoftau contribute pot17_0000.ptau pot17_0001.ptau --name="First contribution" -v
snarkjs powersoftau prepare phase2 pot17_0001.ptau pot17_final.ptau -v
snarkjs groth16 setup build/face_auth.r1cs pot17_final.ptau face_auth_0000.zkey
snarkjs zkey contribute face_auth_0000.zkey face_auth.zkey --name="Key contribution" -v
snarkjs zkey export verificationkey face_auth.zkey face_auth.vkey.json
```

Copy to `web/public/zk/`:
```
mkdir web/public/zk
copy build/face_auth_js/face_auth.wasm web/public/zk/face_auth.wasm
copy face_auth.zkey web/public/zk/face_auth.zkey
copy face_auth.vkey.json web/public/zk/face_auth.vkey.json
```

Generate Solidity verifier (optional if not already present):
```
snarkjs zkey export solidityverifier face_auth.zkey ../contracts/FaceAuthVerifier.sol
```

## Supabase
Tables (SQL editor):
```
create extension if not exists pgcrypto;

create table if not exists face_templates (
  wallet text primary key,
  payload jsonb not null,
  updated_at timestamptz default now()
);

create table if not exists proof_submissions (
  id uuid primary key default gen_random_uuid(),
  wallet text not null,
  proof jsonb not null,
  public_signals jsonb not null,
  commitment text,
  nonce text,
  chain_id bigint,
  created_at timestamptz default now()
);
```

Note: Only encrypted face templates are stored in Supabase.

## Relayer (optional)
The relayer stores proof submissions off-chain (optional if you only use on-chain auth).

Start:
```
cd relayer
npm install
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... npm run dev
```

Endpoints:
- `POST /proofs` store proof submission
- `GET /proofs` list submissions

## How auth works
1) Enroll: liveness + template -> Poseidon commitment stored on-chain with nonce.
2) Login check: compares live face to encrypted cloud template.
3) Submit auth proof: generates Groth16 proof and calls `submitAuthProof` on-chain.
4) Realtime proof stream: reads `IdentityMinted`, `IdentityRevoked`, `AuthProofSubmitted`.

## Troubleshooting
- `commitment mismatch`: enrollment commitment and proof input differ. Re-enroll after contract upgrades.
- Proofs not in stream: check contract address, block window, and event signatures.
- `circom` not found: install circom and add to PATH.
